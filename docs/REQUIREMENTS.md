# 📹 CCTV Collector Service (视频流采集守护服务)

> **项目定位**：针对局域网智能监控摄像机（TP-LINK TL-IPC44AW 等）的 7×24 小时高可靠视频流采集与本地分段缓冲守护服务。
> **核心架构理念**：遵循“采集与上传完全解耦”的两段式设计，确保本地录制绝不受外部云盘网络抖动、限流或鉴权过期的影响。

---

## 1. 业务背景与目标 (Background & Goals)

### 1.1 业务背景
家庭局域网部署了 TP-LINK TL-IPC44AW 智能摄像机，负责室内走廊/通道的安全监控。为了实现监控录像长期归档至云端网盘（如阿里云盘、百度网盘等），同时避免实时直推云盘导致带宽争抢、网络断连丢帧等问题，构建一套两段式解耦的录像流水线：
- **第一阶段（本项目）**：`CCTV Collector` 负责从局域网 RTSP 视频流中实时抓取视频并无损切片（15/30分钟），安全缓冲暂存于内网存储（如 StarFive 节点挂载盘或 Radxa 本地缓冲）。
- **第二阶段（关联组件）**：`CCTV Batch Uploader` 独立批处理任务，从缓冲目录扫描已完成切片，通过 Alist WebDAV 批量推送至云端网盘并执行过期轮转与清理。

### 1.2 核心目标
1. **零转码低开销**：直接复用摄像机的 H.265 (HEVC) 视频流与 AAC 音频流，执行无损封装（Stream Copy），CPU 占用控制在 2% 以下。
2. **工业级高可靠**：具备心跳探活、网络异常自动重连、FFmpeg 僵尸进程回收及优雅停机（Graceful Shutdown）。
3. **精准分段**：利用时间戳规则切片，切片切换瞬间无缝衔接，保障安防录像不丢帧、不跳秒。
4. **云原生可扩展**：支持直接作为独立 Java 守护程序运行，亦可容器化纳管加入 K3s 集群调度。

## 3. 功能性需求 (Functional Requirements)

### 3.1 视频采集与切片
- **RTSP 视频流拉取**：通过 `-rtsp_transport tcp` 建立稳定的 RTSP 会话。
- **时间分段策略**：默认切片时长可配置（默认 900 秒 / 15 分钟），文件名格式标准：`cctv_YYYYMMDD_HHmmss.mp4`。
- **文件状态感知**：未写入完成的文件追加 `.tmp` 后缀，写入完毕后原子重命名为 `.mp4`，便于下游 Batch Uploader 无竞争读取。

### 3.2 异常与进程看门狗 (Watchdog)
- **断流恢复**：持续监听底层 FFmpeg 进程状态。若 RTSP 连接中断或摄像机重启，5 秒内自动启动指数退避重连机制。
- **健康度探活**：如果 30 秒内没有新的切片数据产生，判定为死流并主动重启推流子进程。
- **孤儿进程清理**：主程序退出时（SIGTERM/SIGINT），通过 JVM Shutdown Hook 杀灭所有派生子进程，禁止残留后台泄漏。

### 3.3 本地磁盘熔断保护 (Circuit Breaker)
- **剩余空间监控**：每次启动或切片前检查缓冲目录所在磁盘剩余空间。
- **阈值熔断**：若剩余空间低于安全阈值（默认 5GB），暂停采集并输出告警，防止宿主机磁盘写满崩溃。

---

## 4. 非功能性需求 (Non-Functional Requirements)

1. **性能与资源**：
   - 内存占用：JVM 堆内存限制在 128MB 以内；
   - 网络开销：局域网占用 ≤ 2 Mbps，千兆网络利用率 < 0.2%；
2. **可移植性**：纯 Java 17 实现，可通过 `java CctvCollectorService.java` 单文件免编译直跑，也可由 Maven 打包为可执行 Jar 或 Docker 镜像。
3. **可观测性**：控制台标准输出分级日志（INFO/WARN/ERROR），包含切片事件、重连次数、传输速度等关键指标。
